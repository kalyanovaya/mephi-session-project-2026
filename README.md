## Редакция ОС и отличие от условия задания

В PDF требуется **сертифицированная редакция РЕД ОС 8**. По решению пользователя работа выполняется на **стандартной редакции РЕД ОС 8.0.3 — Standard Server Minimal, ARM64 (aarch64)** в UTM на Mac Apple Silicon. Установка без графической оболочки.

Это отклонение от требования к редакции: стандартную установку нельзя представлять как сертифицированную. Наличие SELinux, PAM, ACL и Linux capabilities само по себе не подтверждает соответствие сертифицированной поставке. Сертифицированная редакция поставляется в определённой комплектации, с документацией и условиями применения сертификата; данный стенд эту поставку не воспроизводит. Принятие замены редакции остаётся на усмотрение преподавателя.

Источники производителя: [загрузка стандартной редакции](https://redos.red-soft.ru/product/downloads/), [сертифицированная редакция](https://redos.red-soft.ru/product/edition-sertificate/). Фактические сведения о системе приведены в `os-release` и `system.out`.

## Как устроен доступ

Разработчики создают и редактируют обычные файлы друг друга в `/data/mephi-2026`. Setgid сохраняет группу каталога, default ACL передаёт права новым файлам и подкаталогам. Кураторы могут читать файлы и проходить по каталогам, но не изменять содержимое или создавать записи. Остальным пользователям доступ запрещён; административный root сохраняет системные полномочия.

Наследование относится к стандартному созданию файлов и каталогов. Владелец файла в обычной модели Linux может намеренно изменить его режим или ACL; запрет такого изменения не является свойством default ACL.

Запрет для кураторов подключён именно к PAM-службе `login`, обслуживающей локальные консоли, включая последовательную консоль UTM. Он не заменяет оболочку на `nologin` и не запрещает все виды входа одновременно. Учётные записи имеют обычную оболочку Bash.

В установленном RPM tcpdump исходный режим — 0755, без setUID/setGID (`tcpdump-before.out`). Команда `chmod u-s,g-s` дополнительно гарантирует отсутствие этих битов; права захвата выданы через capabilities.

## Файл shadow

Файл `shadow` в открытом репозитории **обезличен в поле хеша пароля**: хеши заменены на `!REDACTED`, остальные поля сохранены. Он предназначен для проверки структуры и сроков действия паролей, **не для восстановления аутентификации**. Оригинальный `/etc/shadow` сохранён отдельно для личной передачи преподавателю и в Git/GitHub не включён. Пароли, приватные SSH-ключи и токены также не публикуются.

## Запуск и проверка

В UTM открыть `MEPHI RED OS 8`. На самой машине выполнить:

```sh
hostnamectl
findmnt /mephi-web
getenforce
systemctl is-enabled nginx
systemctl is-active nginx
curl http://localhost
```

С Mac страница доступна по `http://127.0.0.1:8080`, SSH — через `RED-OS-terminal.command` (порт 2223). Эти порты привязаны только к loopback Mac.

Конфигурационные файлы здесь — снимки учебного стенда. Не следует копировать `passwd`, `group`, `fstab` или `shadow` поверх файлов другой системы. Для восстановления стенда нужны подходящие пользователи, отдельный второй диск и соответствующая конфигурация виртуальной машины.

Сама транзакция завершилась с `Return-Code: Success` (`update-details.out`). После настройки контекстов и перезагрузки SELinux работает в Enforcing; проверка `restorecon -nv` и `matchpathcon -V` не выявила ошибок (`selinux-cache-check.out`), функциональные проверки прошли.
